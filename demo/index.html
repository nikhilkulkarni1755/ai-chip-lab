3. Concepts, from basics

In the order a multiply travels from an idea to a chip. Each box links to the file in this lab that demonstrates it.

1. MAC: multiply-accumulate

The atom of neural-network arithmetic: acc = acc + a*b. A matrix product is nothing but many of these. Here a and b are signed 8-bit integers and the accumulator is 32-bit, so a long sum does not overflow in practice: the worst case is (−128)² = 16,384 per step, and a signed 32-bit accumulator only wraps after 131,072 such accumulations (231 / 214).

See: rtl/mac_int8.sv, formal/

2. PE: processing element

A MAC plus the registers that hold its accumulator and pass operands on. In an output-stationary design each PE owns exactly one element of the output matrix and keeps adding into it until the dot product is complete.

See: rtl/mac_int8.sv

3. Systolic array

A grid of PEs where data flows rhythmically from neighbour to neighbour, like blood through the heart (systole). Rows of A enter from the left, columns of B from the top, each skewed by one cycle per row/column so that matching operands meet in the right PE at the right time. No PE needs wide global wiring, which is why TPU-style chips are built this way.

See: rtl/systolic_os.sv, tb/test_systolic.py

4. Dataflow: ws / os / is

Which value stays put in the PE: weights (ws), outputs (os) or inputs (is). The choice changes how often each operand must be re-read from memory, so it changes cycles and bandwidth for the same arithmetic. SCALE-Sim models all three; the sweep compares them.

See: arch/, model/, results/sweeps/arch.jsonl

5. Memory hierarchy and roofline

Arithmetic is cheap, moving data is not. The roofline model plots achievable performance against arithmetic intensity (operations per byte moved): below the knee a layer is bandwidth-bound, above it compute-bound. Task 3 checks that SCALE-Sim's stalls agree with this classification layer by layer.

See: model/, results/t3_summary.json

6. RTL: register-transfer level

Hardware described as registers and the combinational logic between them, in SystemVerilog. It is the level at which designers write chips and the input to synthesis.

See: rtl/systolic_os.sv

7. Verification

Showing the RTL is right. Three independent oracles are used: simulation against NumPy integer matmul (random and directed tests, on two different simulators that must produce byte-identical output), a formal proof that the MAC obeys its equation for all inputs, and an equivalence check that the synthesized netlist behaves like the RTL.

See: tb/test_systolic.py, formal/, eqy/, results/t1_summary.json

8. Logic synthesis

Turning RTL into a netlist of standard cells (NAND, flip-flop, ...) from a technology library; Yosys with ABC does this here. The cell count and area it reports are the first real hardware cost numbers.

See: orfs/designs/, results/t2_summary.json

9. Place and route

Floorplan (chip outline, I/O pins, power grid), placement (where each cell sits), clock-tree synthesis (distribute the clock with balanced delay), then routing (metal wires on many layers). OpenROAD runs all of this; utilization is the fraction of the core area occupied by cells.

See: orfs/designs/, results/t2_summary.json

10. Static timing analysis

Checking every register-to-register path against the clock period without simulating. Slack is the margin; WNS is the worst negative slack and TNS the total of all negative slacks. WNS ≥ 0 means the design meets timing. OpenSTA, embedded in OpenROAD, does it. The physical sweep finds the fastest clock that still closes.

See: results/t2_summary.json, results/sweeps/phys.jsonl

11. PDK

The process design kit: the foundry-supplied cell libraries, timing models, layer stack and design rules for a manufacturing process. nangate45 is an open teaching PDK; sky130 is a real open 130 nm process.

See: orfs/designs/

12. GDSII

The final geometry file handed to a foundry (the mask layers). The layout images in the results section are KLayout renders of the GDS that the flow produced; GDS files themselves are large and are not committed.

See: orfs/render.py

Roofline study: arithmetic intensity vs SCALE-Sim's memory-added cycles.

RULES (fixed here, before any result was looked at; the experiment came after the design):
  workload  : 16 synthetic GEMMs (M,N,K) spanning ~2..170 FLOP/byte (square, skinny, GEMV, K-heavy).
  machine   : R x C = 16 x 16 array, 1 byte/word (SCALE-Sim word_size=1), 64 kB SRAM per buffer,
              DRAM interface B = 4 words/cycle. Set through the bundled scale.cfg: InterfaceBandwidth=USER,
              Bandwidth = IfmapSRAMBankBandwidth = FilterSRAMBankBandwidth = B, SRAM banks = 1.
              (In the bundled google.cfg SCALE-Sim reports 0 stall cycles for every layer of every
              dataflow: interface 10 words/cycle with 6 MiB buffers hides everything, so B is lowered.)
  Two roofline variants are reported:
   (a) compulsory:  AI = FLOPs / (M*K + K*N + M*N bytes);  peak = 2*R*C FLOP/cycle; ridge = peak / B;
       predicted bandwidth-bound  <=>  AI < ridge.
   (b) effective:   traffic = DRAM words actually moved in the SCALE-Sim run (DETAILED_ACCESS_REPORT
       ifmap+filter reads + ofmap writes, i.e. including re-fetch when 64 kB cannot hold the working set);
       AI_eff = FLOPs / traffic;  predicted bandwidth-bound  <=>  traffic / B > compute_only cycles
       (memory time exceeds compute time = AI_eff below the layer's attainable-compute ridge).
  compute_only = stall-free cycles of the layer from model/analytic.py (validated exact by the fit).
  SCALE-Sim signal (observed): stall_frac = Stall Cycles / Total Cycles; bandwidth-bound <=> stall_frac > 5 %.
  Also reported: memory_added = (Total Cycles incl. prefetch - compute_only) / Total Cycles incl. prefetch.
  CHRONOLOGY (disclosed): the first rule written down used memory_added > 10 % as the observed signal; the
  first run flagged all 16 layers (the exposed initial prefetch alone exceeds 10 % everywhere), so it could
  not discriminate, and variant (a) turned out to ignore re-fetch traffic. The stall-based observed signal
  and variant (b) were therefore adopted afterwards (post-hoc); all variants are kept in roofline.json.
  Gating checks (variant b): agreement >= 80 % of layers, both classes >= 3 layers,
  Spearman(AI_eff, stall_frac) <= -0.5, for each dataflow.

9. Where to go next

  1. bfloat16 / FP8 processing elements, checked against ml_dtypes
    Modern training and inference chips left INT8-only long ago; a floating-point MAC has a mantissa multiplier and rounding that are easy to get subtly wrong, and ml_dtypes gives a bit-exact oracle.
  2. Double-buffered SRAM modelled with CACTI
    The array is only half the chip; the on-chip buffer decides whether it stays fed, and CACTI turns capacity into area, energy and access time to plug into the roofline.
  3. systolic_os through sky130 and PPA across PDKs
    Comparing the same design on nangate45 and sky130 shows how much of the result is the process rather than the design.
  4. VCD/SAIF switching activity from cocotb for real power
    Power numbers from default activity are guesses; feeding the actual toggle rates of a real matmul to OpenROAD makes them meaningful.
  5. Gemmini/Chipyard, TVM/VTA or MLIR/CIRCT
    Moves from a hand-written array to a full generated accelerator with a compiler stack, which is how real systems are explored.
  6. DREAMPlace
    GPU-style analytical placement; a well-defined component to swap into the flow and compare.
  7. LLM-written RTL scored against VerilogEval
    Uses the same lab as a judge: generated RTL passes only if the simulators and formal tools agree it is right.

1Double-buffered SRAM in the RTL (a ping-pong scratchpad feeding systolic_os)The array is only half the chip. A double buffer is what lets compute overlap DRAM traffic, which is exactly the effect the roofline study could not see in the SCALE-Sim sweeps (the CALC bandwidth mode never stalls). Putting it in RTL makes the stall behaviour measurable instead of modelled.RTL + cocotb: a day of agent time, small sims (minutes). Through ORFS it needs SRAM macros or flop-based memory: flop-based buffers make the design several times larger than systolic_os alone (28 min per flow today), so expect 1-2 h per flow. Use CACTI numbers (stage 63) to size it first.yes, with flop memory and a small buffer; no real SRAM macro on nangate45 here
